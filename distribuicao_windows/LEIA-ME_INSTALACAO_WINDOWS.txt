INSTALADOR DO GERARD PARA WINDOWS
=================================

ARQUIVO PARA O USUARIO FINAL
----------------------------
1. Pegue o arquivo saida/Gerard-1.0.0.exe (gerado pelo script abaixo).
2. Clique duas vezes nele.
3. O instalador copia o Gerard e um runtime Java 22 privado (embutido no
   proprio EXE, sem download) para %LOCALAPPDATA%\Gerard, cria atalho na
   Area de Trabalho e no menu Iniciar e abre o programa ao final.
4. Nao e necessario instalar Java manualmente, ter internet durante a
   instalacao, nem usar uma conta de administrador.

Este EXE e produzido pelo jpackage (JDK) com um runtime minimo gerado via
jlink e embutido no instalador — por isso o Java vai "acoplado" junto do
Gerard, e o pacote inteiro roda offline a partir do momento em que o EXE
foi baixado.

ATUALIZACAO
-----------
Gerar um novo EXE (veja abaixo) e reinstalar substitui os arquivos em
%LOCALAPPDATA%\Gerard.

DESINSTALACAO
-------------
Use "Gerard" em Configuracoes > Aplicativos (instalacao por usuario, sem
precisar de administrador).

INTEGRIDADE DOS ARQUIVOS EMBUTIDOS
----------------------------------
Ver distribuicao_windows/SHA256SUMS.txt para o hash de cada arquivo gerado
na build mais recente (app/Gerard.jar e saida/Gerard-1.0.0.exe).

COMO GERAR O EXE (para quem for reconstruir a partir do codigo-fonte)
-----------------------------------------------------------------------
Pre-requisitos, todos em Windows:
- JDK 17+ com jpackage (testado com JDK 22).
- WiX Toolset v3 (candle.exe/light.exe) no PATH — necessario para o
  jpackage gerar --type exe no Windows.

Passos:
1. Compile o projeto e gere distribuicao_windows/app/Gerard.jar com
   Main-Class=Main e Class-Path apontando para lib/weka-stable-3.8.6.jar
   e lib/bounce-0.18.jar (copie essas duas libs para
   distribuicao_windows/app/lib/).
2. Execute distribuicao_windows/GERAR_EXE_COM_JPACKAGE.bat. Ele chama o
   jpackage com --input app --main-jar Gerard.jar --icon Gerard.ico e
   grava o instalador em distribuicao_windows/saida/Gerard-1.0.0.exe.
3. app/, saida/ e saida_exe/ sao gerados localmente e ficam fora do git
   (ver .gitignore) porque sao regeneraveis a partir do codigo-fonte e
   grandes demais (o EXE final passa de 100 MB por trazer o runtime Java).

LIMITACOES
----------
- O EXE final e grande (runtime Java completo embutido), entao ele precisa
  ser distribuido por um meio que aceite arquivos grandes (pendrive, link
  de download proprio) — nao por e-mail comum.
- Windows ou o antivirus pode exibir uma advertencia porque o EXE nao tem
  assinatura digital. A assinatura exige um certificado de codigo do
  distribuidor (pago).
- O runtime embutido cobre o AWT/Swing usado pelo Gerard; nao inclui
  JavaFX. Visualizacoes que dependiam de JavaFX continuam abrindo no
  navegador, como ja acontecia antes.
